# PaddleOCR text recognition in Node (ONNX) — step 0 spike

This branch proves that a PaddleOCR PP-OCRv5 recognition model can run inside the offline app **without Python**: the model is exported to ONNX and executed with `onnxruntime-node`; preprocessing and CTC decoding are reimplemented in JavaScript (`js/main/paddle-rec.js`). It is not wired into `ocr-service.js` and does not replace Tesseract.

## Why not use the stock model for Vietnamese

`latin_PP-OCRv5_mobile_rec` (the model PaddleOCR documents for `vi`) lacks 90 of the 178 Vietnamese letters in its character set (ạ ả ấ ầ ẩ ẫ ậ ằ … ỵ and their capitals). On 100 printed Vietnamese names / timesheet labels it reads **11/100** exactly; e.g. "Phạm" → "Phm", "Đỗ" → "Đ", "Hằng" → "Hàng", with confidence 94–98%. The default `vi` pipeline model (PP-OCRv6 medium) lacks 44 of the same letters. A retrained recognition head is required; see the dictionary below.

## Measured results (stock latin model, before retraining)

244 crops: 144 cells the app itself cut from the synthetic fixtures (printed table, 5° tilt, phone-photo simulation, handwritten x marks, shift schedule, vertical schedule, MNIST digits) plus 100 printed Vietnamese text lines.

- Recognised text identical to PaddleOCR Python (`paddle_static`, batch size 1): **244/244**. Score difference max 0.007, mean 0.0004.
- Resize is bit-compatible with `cv2.resize(INTER_LINEAR)` on uint8 (OpenCV fixed-point arithmetic, coefficients × 2048): at most ±1 grey level on ≤ 0.5% of pixels; preprocessing tensor matches PaddleX `OCRReisizeNormImg` within one quantisation step.
- Speed on the development PC (CPU): **~18–21 ms per cell** in Node vs ~209 ms per cell for PaddleOCR Python with oneDNN disabled (oneDNN crashes on Windows with paddlepaddle 3.3.1).
- Footprint: model 8.0 MB + `onnxruntime-node` Windows x64 CPU binaries ≈ 29 MB (`onnxruntime.dll` + binding). The DirectML / dxcompiler DLLs (≈ 38 MB) are not needed for CPU inference; verified by running without them.

All images are synthetic; this measures parity and speed, not accuracy on real timesheets.

## Export a model to ONNX

`paddle2onnx` 2.x fails to load its native module on Windows with paddlepaddle 3.3.1 (`DLL load failed … The specified procedure could not be found`), so conversion runs on Linux/WSL. One-time setup and usage are in the header of `js/scripts/paddle/convert.sh`:

```bash
bash js/scripts/paddle/convert.sh <paddle export dir> <out dir>   # → inference.onnx, inference.yml, dict.json
```

The script checks that the ONNX output has `len(dict) + 2` classes (blank + characters + space).

## Use

```js
const { createPaddleRecognizer } = require('./HAK_OCR_ENGINE');
const rec = await createPaddleRecognizer({ model: dir + '/inference.onnx', dict: require(dir + '/dict.json') });
const { text, score } = await rec.recognize({ data: grayUint8, w, h });   // or rec.batch(items) → [{ text, conf 0–100 }]
await rec.release();
```

`onnxruntime-node` is an optional peer dependency and is loaded only when a recognizer is created. Results are suggestions; the host decides how they are compared with Tesseract and must keep human review.

## Vietnamese training dictionary (step 1)

`js/ocr/paddle/vi_latin_dict.txt` = the 836 lines of `ppocrv5_latin_dict.txt` **unchanged and in order** (so the pretrained output rows keep their meaning) + the 90 missing Vietnamese letters appended = 926 lines. Built by `js/scripts/paddle/vi-charset.cjs`, which also exports `uncovered(label, dict)` to reject training labels containing characters outside the dictionary (labels are NFC-normalised first). Use it as `Global.character_dict_path` when retraining from `latin_PP-OCRv5_mobile_rec_pretrained.pdparams`.

## Tests

- `js/tests/unit/paddle-rec.test.js` — resize vs `cv2`, preprocessing vs PaddleX, CTC decoding, recognizer contract with a fake ONNX Runtime; and full recognition parity against PaddleOCR Python on 32 app crops when `HAK_PADDLE_MODEL_DIR` (with `inference.onnx` + `dict.json`) and `onnxruntime-node` are available (skipped otherwise).
- `js/tests/unit/vi-charset.test.js` — dictionary prefix, coverage of all Vietnamese letters, digits and timesheet symbols.
- Fixture `js/tests/fixtures/paddle/parity.json.gz` is generated by `js/scripts/paddle/make-parity-fixture.py` from cv2 / PaddleX / PaddleOCR themselves; crops come from synthetic fixtures only.
